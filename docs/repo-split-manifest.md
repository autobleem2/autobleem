Where every tracked file goes when the launcher repo is split (`docs/repo-split-analysis.md`). Generated by
classifying all 1327 tracked files by path; the counts and the ambiguous set below are from that pass
(2026-09-22). This is the mechanical map the `git filter-repo` extractions follow — one file, one target
repo, full coverage.

Genuinely debatable: `format.sh`/`lint.sh`/`lang_tools.py` are used by more than one C++ repo — either they
live in `autobleem-build` and are fetched, or each repo carries a copy (the emulators already carry their
own toolchain files, so per-repo copies are the established pattern). `theme_convert` links `ableem_engine`,
so wherever it lands it needs the `autobleem-core` submodule.

## Mechanics

- Extract with `git filter-repo --path <p1> --path <p2> …` (the path list per repo above) from a clone, so
  the source is untouched until cutover. The classifier that produced this manifest can be kept in
  `autobleem-build` and re-run to regenerate the path lists.
- The kernel payload (`payload/Apps/abflashkit/kernel/`, 27 MB) travels with `autobleem-console-tools`; it is
  rebuildable by `autobleem/psc-kernel-payload`, so a later step can drop the checked-in binaries and fetch
  them instead.
- Every "assembly" input (per-target binaries, themes, samples) is pulled as a published artifact by
  `autobleem-appliance`, per the compile-once model — the appliance repo holds scripts, not binaries.
